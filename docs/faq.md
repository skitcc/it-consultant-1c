# База знаний IT-консультанта (тестовая)

Документ для проверки RAG: индексации в Qdrant и ответов почтового шлюза.
Ниже — вымышленные, но реалистичные инструкции по типичным вопросам сотрудников.

---

## 1. Обмен данными в 1С

### Как настроить обмен между двумя базами

1. Откройте базу-источник под пользователем с правами администратора.
2. Перейдите: **Администрирование → Синхронизация данных → Настройки синхронизации данных**.
3. Нажмите **Создать** → выберите сценарий **Синхронизация данных через универсальный формат** (или обмен по правилам, если так принято в компании).
4. Укажите код этой информационной базы, например `ERP01`.
5. На стороне базы-приёмника создайте парную настройку с кодом `ERP02` и тем же префиксом обмена.
6. Выберите каталог обмена на сетевом диске, например `\\fileserver\1c-exchange\erp01-erp02`.
Оба сервера 1С должны иметь доступ на чтение/запись в этот каталог.
7. В расписании поставьте обмен каждые 15 минут в рабочее время (09:00–19:00).
8. Выполните **Интерактивный обмен** один раз вручную и проверьте журнал регистрации.

### Типичные ошибки обмена

- **Ошибка доступа к каталогу обмена** — проверьте SMB-права учётной записи службы 1С (`NT SERVICE\1C:Enterprise 8.3 Server Agent` или доменная учётка сервиса).
- **Конфликт уникальности ссылок** — у баз должны быть разные префиксы объектов (2–3 символа).
- **Сообщение «Версия формата не поддерживается»** — обновите расширения/правила обмена до одной версии на обеих сторонах.
- **Обмен «висит»** — посмотрите блокировки в консоли кластера и размер файлов в каталоге обмена; файлы старше 7 дней можно архивировать.

### Как принудительно запустить обмен

В базе: **Администрирование → Синхронизация данных → Синхронизировать**.
Либо из консоли кластера перезапустите регламентное задание `СинхронизацияДанных`.

## 2. Печать и подключаемое оборудование

### Принтер чеков не печатает

1. Убедитесь, что устройство видно в Windows: **Параметры → Bluetooth и устройства → Принтеры**.
2. В 1С откройте **Администрирование → Подключаемое оборудование** и проверьте, что драйвер в статусе **Подключено**.
3. Для АТОЛ используйте драйвер ККТ из пакета «Драйверы торгового оборудования» версии, совместимой с вашей платформой 8.3.
4. Проверьте COM/USB порт: если виртуальный COM сменился после перезагрузки, обновите номер порта в карточке оборудования.
5. Тест: кнопка **Тест устройства**. Если тест не проходит — проблема вне 1С (драйвер/кабель/права).

### Не печатается этикетка

- В обработке печати выбран правильный принтер этикеток, а не обычный офисный.
- Размер этикетки в макете совпадает с физическим (например 58×40 мм).
- В драйвере принтера отключён параметр «подгонять страницу под A4».

## 3. Доступ пользователей и блокировки

### Пользователь не может войти в базу

1. Проверьте, что пользователь есть в списке пользователей ИБ и не помечен на удаление.
2. Если используется доменная аутентификация — пользователь должен быть в группе AD `1C-Users-ERP`.
3. Если пароль 1С — сбросьте его администратором: снимите флажок «Аутентификация 1С» → сохраните → снова включите и задайте временный пароль `Welcome1C!`.
4. При ошибке «Превышено максимальное число одновременных сеансов» освободите сеансы в консоли кластера или увеличьте лимит лицензий.

### База заблокирована монопольно

Сообщение «Ошибка исключительной блокировки» значит, кто-то держит монопольный доступ
(обновление конфигурации, тестирование и исправление, выгрузка в dt).

Что делать:
1. В консоли администрирования кластера найдите сеансы с приложением `BackgroundJob` / `Configurator`.
2. Свяжитесь с сотрудником, который запустил обновление.
3. Не завершайте сеанс конфигуратора во время обновления структуры БД — можно повредить базу.

## 4. Резервное копирование

### Где лежат бэкапы

- Ежедневные копии файловых баз: `\\backup\1c\daily\YYYY-MM-DD\`.
- Хранятся 14 дней, затем ротация.
- SQL-базы: полный backup в 02:00, diff каждые 4 часа на `\\backup\1c-sql\`.

### Как восстановить файловую базу из backup

1. Остановите доступ пользователей (блокировка начала сеансов).
2. Скопируйте папку базы из `\\backup\1c\daily\...` на рабочий путь.
3. Проверьте наличие `1Cv8.1CD`.
4. Откройте базу через конфигуратор → **Тестирование и исправление** (только проверка ссылочной целостности).
5. Снимите блокировку сеансов.

Восстановление может делать только группа `1C-Admins`. Обычным пользователям выдать dt/backup нельзя.

## 5. VPN и удалённый доступ к 1С

### Публикация тонкого клиента

Адрес публикации для сотрудников: `https://1c.company.local/erp`.
Требования:
- VPN корпоративный (WireGuard профиль `corp-vpn`) должен быть подключен.
- На ПК установлен тонкий клиент платформы **8.3.25** или новее.
- В исключениях антивируса добавлен каталог `%LOCALAPPDATA%\1C`.

### Медленная работа через VPN

- Проверьте пинг до `1c.company.local`: норма до 40 мс, при >100 мс ожидайте тормоза форм.
- Не используйте файловый режим базы через VPN — только клиент-серверный.
- Крупные отчёты запускайте на сервере (регламентным заданием), а не с домашнего ноутбука.
